# Staff administration interface draft

Owner request: create an interface for adding users with roles and managing roles and users. This continues Phase 4 access foundation; it is not approval to grant named people access.

Reference: A22 (331:9365) in the binding Figma file. Design context, metadata and screenshot were read. Reuse Inter/navy tokens, Panel, Button, StatusBadge, ConfirmDialog and the existing shield icon. Roles, Staff, Access requests and Sessions follow the A22 structure. The matrix displays caller-provided canonical capabilities and actual role grants; it does not turn design proposals into live defaults.

Implemented component: StaffAccessPage has a role/capability matrix, masked staff directory and filtering, invite form, role creation/edit form, staff role/status/scope editor, explicit area selection, confirmation and reason, and an async request adapter boundary. Success copy describes a pending independent review rather than activated access. Controls are disabled if the adapter, permission or current data is unavailable. There are no embedded staff records, credentials, network writes or automatic assignments. UI form commands are view models, not duplicate API response types; responses use generated canonical types.

This is a draft and is deliberately not mounted into the live app. Access-request and session panels accept connected components; absent adapters show explicit unavailable states. Tests cover permission denial, disconnected writes, masked filtering and required role/area selection. Local execution is blocked because the workspace sandbox configuration contains file:///workspace, which is invalid on Windows. GitHub CI must validate the component. A22 rendering, bilingual copy, complete API adapters, reauthentication, independent-approval workflow, invitation acceptance and live staging checks remain required before enabling the route. This draft does not claim those features are complete.
